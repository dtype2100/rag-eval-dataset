# 공개 서비스 자료 주제 추가와 3회 검증

작성일: 2026-10-28. 사용자 요청: “주제 추가 및 검증 3회”.

## 범위

추천한 핵심 주제 3개를 추가하고 각 주제를 3회 검증한다(총 9개 검증 단위).
기존 코드·전역 스킬을 재사용하고, 자료의 해시·원본 위치/표 셀까지 대조하는 작은 검증 도구만 추가한다.

| 주제 | 공개 공식 자료 | 추가로 확인할 것 |
|---|---|---|
| 정책·FAQ | GitHub Copilot 개인 구독·변경 정책 | 적용 조건, 취소 시점, 예외, 근거 결합 |
| 상품·요금표 | Cloudflare Workers 가격·한도 | 일/월, 포함량/초과량, 단위, 표 셀, 실제 산술 |
| 기술지원 | Kubernetes Pod 수명·이미지·디버깅 문서 | 오류 문자열, 증상과 원인 구분, 진단 조치, 로그 부족 |

자료·과업은 사용자가 승인한 주제 추가 요청에 따라 구현자가 선정한 제안이다. 사용자가 특정 서비스나 정답 라벨을 제공했다고 기록하지 않는다.
현재 프로젝트에 운영 RAG 연결·고객 질의 로그가 제공되지 않았고, 로컬 임베딩 실행 라이브러리/모델도 확인되지 않았다.
따라서 실제 공개 원문을 이용한 평가셋 생성·검증 사례이며, 운영 RAG·실제 사용자 로그·임베딩 모델 성능이나 고객 효과를 검증했다고 주장하지 않는다.
질문은 모두 `origin=synthetic`으로 표시하고 최신 서비스 전체가 아닌 고정 스냅샷의 범위에서 판정한다.
이미지·음성 주제는 이 텍스트/표 검증으로 지원이 입증되지 않으며 후속 범위로 남긴다.

## 작업 파일

- `examples/public-cases/{policy,pricing,support}/`: 데이터셋, 출처·라이선스, 사례 설명, 회차별 검증 결과. 공개 가능한 자료만 기록.
- `data/public-cases/`: gitignore된 원문 스냅샷. 공식 원문 URL·고정 커밋·SHA-256으로 다시 받을 수 있게 한다.
- `scripts/verify_public_cases.py`: 기존 계약 검사 + 원본 해시 + 텍스트 offset/코드 줄/표 셀 대조; 필요한 경우 명시적 `--fetch`로 고정된 공식 GitHub 원문만 확보.
- `tests/test_public_cases.py`: 원문·위치·표 셀·경로 경계 회귀 검사.
- `docs/public-case-results.md`, 기존 `README.md`·스킬 참조·공개 보고 사이트: 검증 결과와 한계 반영.

## 세 회차와 통과 기준

1. **원문·구조 검증:** 고정 커밋, 원본 해시, 위치/셀, 계약, 수치 계산을 확인한다. 실제 조회한 출처와 파생 자료의 연결을 기록한다. 작성자는 자신의 문항을 accepted 처리하지 않는다.
2. **독립 내용 검토:** 다른 주제 작성자가 원문과 질문만 보고 먼저 독립 답변을 작성한다. 그 뒤 생성 정답·근거와 비교하고, 잘못된 조건·단위·무정답을 수정하거나 제외한다. 사람 검토로 표시하지 않는다.
3. **오류 주입·재현 검증:** 수정된 최종본에 대해 해시/근거 위치/근거 집합/누출/자기검토 오류가 차단되는지 확인한다. 최종본을 동결 후 재검증하고, 원문 재확보와 전체 테스트·CI를 재현한다.

표본 수는 주제당 약 10~12개를 목표로 하되, 근거가 없는 문항을 수량에 맞춰 보충하지 않는다.
소규모 파일럿의 통과는 통계적 성능 보증이나 모든 자료 지원의 증거가 아니다.
같은 검증 명령을 단순히 세 번 실행한 것을 세 회차로 세지 않는다.

## 검토한 실행 선택

운영 설정을 추측하거나 API 키·모델을 새로 발급하지 않는다. 공개 원문과 현재 에이전트로 가능한 검증을 수행한다.
기존 rag-eval 0.1.0은 대체/결합 근거를 손실 없이 표현하지 못하므로 강제 변환해 검색 점수를 만들지 않는다.
이번 공개 서비스 사례에서 실제로 확인한 범위만 기존 공개 사이트와 GitHub에 작업 단위별 기록한다.
