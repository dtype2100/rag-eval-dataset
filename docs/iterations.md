# 세 차례 개선·테스트·검증 기록

초기 구현 기준: 독립 행동 시나리오 3개 확인, 자동 테스트 22개 통과, 합성 원문 2개와 문항 3개의 해시·위치·정답을 별도 LLM이 대조했다.
각 회차는 기존 테스트 전체를 유지하고, 관찰된 결함을 재현한 뒤 필요한 개선만 반영한다. 아래는 실행 전 계획이며 결과는 실행 뒤 채운다.

## 1회차 — 관련성 판정과 무정답의 확인 범위

부족점: qrels의 숫자는 있지만 “이 업무에서 무엇이 관련인가”와 판정 후보 범위가 번들에 강제되지 않는다.
abstain rationale의 자유 문장만으로는 전수 확인과 제한 검색을 기계적으로 구별할 수 없다.

외부 조사:

- [KILT](https://aclanthology.org/2021.naacl-main.200/): 고정 지식 스냅샷에서 과업 결과와 provenance를 함께 평가한다.
- [TREC 2024 overview §2.1.3](https://trec.nist.gov/pubs/trec33/papers/overview_33.pdf): pooling의 다양성·깊이와 불완전 qrels가 평가에 미치는 영향을 설명한다.

채택: `judging`에 과업별 관련성 기준·후보 범위·판정 범위를 기록하고, 거절 문항에 구조화된 `answerability_check`를 추가한다.
비채택: 전 코퍼스 전수 라벨링의 일괄 강제. 큰 코퍼스에서는 현실적이지 않으므로 제한 검토와 그 한계를 명시한다.

테스트 계획: 관련성 기준 누락 동결, 전수 확인 선언인데 출처 일부만 기록한 거절, 제한 검토인데 한계가 빈 번들을 각각 거절해야 한다.
검증 계획: 전체 테스트, 예제 원본 연결·동결 재검증, 새 컨텍스트에서 미판정/무정답 구별 시나리오를 확인한다.

결과: 신규 회귀 테스트 3개가 기존 구현에서 실패하는 것을 확인한 뒤 수정했다. 전체 25개 테스트 통과.
예제 원본 SHA-256·텍스트 위치 대조와 freeze→validate도 통과했다.
새 컨텍스트 행동 검사에서 1,000개 규정 중 일부 검색결과만 읽은 무정답 20개를 확정하지 않았고, bounded/전수 확인과 미판정/0을 구별했다.
판정: 채택한 필드·절차를 유지한다. 1회차 완료.

## 2회차 — 생성 이력과 데이터 분리

부족점: 생성 방법·모델/작성자·프롬프트/설정 이력이 필수 계약이 아니었다. 동일 한국어의 Unicode 조합 차이나 동일 바이트 출처의 다른 집단명으로 분리 검사를 우회할 수 있는지 확인한다.

외부 조사:

- [Datasheets for Datasets](https://arxiv.org/abs/1803.09010): 목적·구성·수집 과정·권장 사용의 문서화 원칙.
- [Stop Uploading Test Data in Plain Text](https://aclanthology.org/2023.emnlp-main.308/): 공개 평가셋이 이후 모델 학습에 노출될 수 있는 오염 문제.

채택: 생성 provenance, NFC 정규화 질의 검사, source-disjoint에서 원본 해시 교차 검사, 비공개 holdout과 공개 예제의 구별.
비채택: 암호화/권한 서버 신규 개발과 오염 완전 탐지 약속. 외부 학습 이력을 알 수 없으며 이번 스킬 범위를 넘는다.

테스트 계획: 생성 이력 누락 동결, NFC/NFD 동등 한국어 질문 교차, 다른 split_group을 붙인 동일 SHA-256 출처 교차의 실패를 먼저 재현하고 수정 후 전체 테스트를 실행한다.
검증 계획: 출처·생성 이력을 예제와 대조하고 새 컨텍스트가 이력 없는 확정·누출을 올바르게 보류하는지 확인한다.

결과: 새 회귀 테스트 3개가 기존 구현에서 실패한 것을 확인했다. provenance 누락, NFC/NFD 동등 질문, 동일 해시 출처의 분리 우회를 보완하고 전체 28개 테스트가 통과했다.
예제는 확인 불가능한 모델 ID와 통제하지 않은 seed를 정직하게 명시했고 freeze→validate 및 스킬 포맷 검증도 통과했다.
새 컨텍스트는 반복 튜닝 test셋을 dev로 재분류하고, 공개 예제와 비공개 holdout을 구별하며 모델 ID·seed를 추측하지 않았다.
판정: 확인된 세 결함의 수정과 이력·오염 지침을 유지한다. 2회차 완료.

## 3회차 — 판정 신뢰성과 최종 배포 검증

계획: LLM 판정 편향·평가 불확실성 관련 1차 자료를 조사한다. 새 컨텍스트 전체 코드 리뷰와 적대적 입력 검사에서 나온 실질 결함을 보완한다.
테스트 계획: 재현 가능한 결함과 판정 교정 시나리오를 테스트하고 전체 테스트·호환 Python CI를 실행한다.
검증 계획: 깨끗한 복제본의 문서 명령, 스킬 포맷·참조, 해시·동결·원격 HEAD·GitHub 공개 상태·Sites 공개 배포를 확인한다.

결과: 미시작.

## 해석의 한계

자동 테스트 수는 RAG 품질 점수가 아니다. LLM 시나리오 표본은 에이전트 일반 성공률을 증명하지 않는다.
실제 고객 데이터·운영 RAG·OCR/멀티모달 파서를 실행하지 않았으며 이 범위의 성능은 주장하지 않는다.
