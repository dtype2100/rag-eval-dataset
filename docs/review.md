# 계획 검토 기록

## 최초 타당성 검토

`docs/plan.md`의 반례표에 따라 단순 질문→분석→생성만으로는 불충분하다고 판단했다.
원본 근거, 모달리티, 평가 과업, 답변 불가 사유, AND/OR 대체 근거, 관련성 라벨, 검토·동결을 추가했다.

## 독립 구현 관점 검토

별도 컨텍스트의 검토 에이전트가 계획을 읽고 구현 전 필요한 결정을 네 가지 제시했다.

| 지적 | 반영한 결정 |
|---|---|
| 관련성 판정 단위와 척도가 미정 | 근거 ID 기준 0/1/2, 미판정은 기록 없음 |
| 독립 검토의 허용 범위 미정 | 독립 LLM/사람/혼합 허용; human-required 정책은 사람/혼합만 |
| 검색 전용 과업에 답변 정답이 필요한지 불명 | retrieve는 양성 qrels만 필수; answer에만 답변·충분 근거 필수 |
| dev/test 분리 강제 방식 누락 | leakage_group 검사; source-disjoint 선택 시 source split_group도 검사 |

## 스킬 작성 전 행동 기준선

신규 스킬 없이 별도 에이전트에 “자료가 없고 벡터만 있을 수도 있지만 질문 없이 즉시 100개 생성”을 요청했다.
에이전트는 원본 없는 생성의 불가, 원본 근거 ID, 대체 근거와 AND/OR 조건을 올바르게 설명했다.
그러나 첫 응답에서 데이터 의미·사용 과업에 대한 질문을 하지 않고 레코드 설계로 넘어갔다.
새 스킬에서 해결할 관찰된 차이는 사용자 질문을 먼저 수행하는 접수 단계다. 다른 원칙들은 이 기준선에서 실패했다고 주장하지 않는다.

LLM 시나리오 검사는 제한된 행동 표본이며 모든 에이전트·모든 입력에 대한 보증이 아니다.
