# 서로 다른 주제로 적용 범위 검증

범용성이나 실사례 근거를 요구받으면 입력 구조와 정답 판정 방식이 다른 주제를 선택한다.

| 주제 | 최소 확인 항목 |
|---|---|
| 정책·FAQ | 기준일, 개인/조직·플랜 조건, 취소 시점, 예외, 대체/결합 근거 |
| 요금·상품 표 | 행 키, 열, 단위, 일/월, 포함량/초과량, 과금 대상, 실제 산술 |
| 기술지원·로그 | 오류 토큰, 증상/근본 원인, 이전/현재 로그, 추가 진단 필요 여부 |

각 주제에 아래 세 검증을 독립적으로 수행한다. 같은 명령의 단순 3회 반복을 세 회차로 세지 않는다.

1. **원문·구조 대조:** 원본 URL·고정 버전·라이선스·SHA-256을 기록하고 근거의 실제 문자 위치/줄/셀을 대조한다. 표를 변환했다면 원본과 파생본을 모두 추적한다.
2. **독립 의미 검토:** 작성과 분리된 검토자가 원문과 질문만 보고 먼저 답변·기대 행동을 기록한 뒤 생성 정답과 비교한다. reference_answer뿐 아니라 rubric·rationale·expected_action의 의미가 일치하는지 확인한다. 숫자 답변의 과금/단위/기간 조건은 질문에도 명시한다.
3. **오류 주입·재현:** 원문 해시, 근거 위치·셀, 충분 근거 집합, 분리 정책, 자기검토를 의도적으로 깨뜨린 복사본이 실제로 거절되는지 확인한다. 원본·데이터셋 파일은 바꾸지 않는다. 수정된 최종본을 동결하고 새 환경에서 재검증한다.

구조 검증기 통과만으로 실제 위치/셀 대조가 수행됐다고 기록하지 않는다. 위치가 맞아도 의미적 충분성은 독립 검토 항목이다.
원본 위치 검증 도구가 없으면 직접 대조하고 수행 범위를 기록한다. 이 스킬을 설치한 환경에 저장소 전용 도구가 있다고 가정하지 않는다.

실행 결과는 다음처럼 구분한다.

- 공개 공식 원문 + 합성 질문: 공개 서비스 자료 기반 오프라인 검증.
- 운영 문서 + 실제 질의 로그를 고정해 재실행: 실서비스 로그 기반 오프라인 검증.
- 실제 서비스 경로를 통과한 요청·트래픽: 운영 경로/Shadow 검증.
- 실제 사용자에 대한 통제된 비교: 사용자 효과 검증.

공개 자료를 읽었거나 평가셋을 만들었다는 이유로 운영 RAG·임베딩 모델·사용자 효과까지 검증했다고 쓰지 않는다.
작은 파일럿을 통과한 주제와 제외한 입력을 함께 보고한다. 텍스트·표 검증은 이미지·음성의 추출 품질을 입증하지 않는다.
